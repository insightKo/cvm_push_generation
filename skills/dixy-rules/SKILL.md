# Назначение
Единый свод требований Елены (заказчик, аналитик CVM) к работе над акциями и коммуникациями ДИКСИ. Каждый агент проекта читает этот файл целиком до начала работы и выполняет его буквально. Правила накоплены с марта по сентябрь 2026 как обратная связь на реальные ошибки — это не рекомендации, а условия приёмки.

# 1. Рабочий процесс
1. **Правка → «проверь» → ждать явного ОК → только потом commit/push/deploy, запись в Google-таблицу, копирование на сервер.** Молчание ≠ согласие. «Дай ссылку» ≠ разрешение на публикацию. Правило продублировано в CLAUDE.md проекта и глобальном — жёсткое.
2. **Любая задача по акциям: прогноз → варианты подхода на выбор → согласование → реализация.** Логика отбора клиентов, разбиение аудитории, размер выгоды, пороги — решения Елены. Менять их «чтобы показать» нельзя.
3. **Главное правило аналитика: сначала словами описать, каких клиентов берём, почему, сколько их и чем рискуем → ОК → только потом SQL.** Никакого кода до согласования аудитории.
4. **Ничего не запускать без явного «давай»**: ни AI-генерацию, ни тестовые скрипты, ни приложение, ни статические проверки. Показать правку → ждать решения.
5. **Не добавлять непрошеное**: без блоков «что согласовать», контрольных списков, «варианты дальше», «моё наблюдение», deeplink-комбо, плейсхолдеров «До [дата]». Ответ = ровно то, что спросили.
6. **Не вставлять собственные выводы** в материалы (слайды, таблицы, файлы): никаких takeaway-плашек, бейджей «НОВОЕ», оценок эффекта, которые Елена не произносила. Любой вывод — согласовать до вставки.
7. **После правок выводить полную картину целиком** — все материалы всех блоков сразу, не «выше по треду», не по одному.
8. **Не подключать источники и файлы проекта к логике по своей инициативе** — каждый раз спрашивать, можно ли использовать файл и что он означает сейчас (файлы в data/ бывают историческими артефактами).
9. **Никаких экспертных порогов**: границы сегментов, доли, «топ-N%» — только из данных (кластеризация, распределения) или по согласованию.
10. **Входы моделей — свежие данные из БД** за актуальное окно, в том же SQL; статичные снапшоты (ассортимент.xlsx) — только для названий или после согласования.
11. Для приложения: принципиальные изменения UI согласовывать до правки; после любого фикса — прогон тестов и проверка смежных экранов; фильтр «Месяц» по умолчанию открывается на последнем месяце списка.
12. Сроки в материалах — номером недели и датами: «37 неделя (07.09.–12.09.)», номер считать по ISO-календарю, не «на следующей неделе».
13. **Любой SQL-скрипт до выдачи — ревью на оптимальность агентом `sql-senior`** (`skills/sql-senior/SKILL.md`): тяжёлые подзапросы, повторные сканы чеков, несаргабельные условия, циклы, повторный прогон. Смысл отбора ревью не меняет. Решение Елены 14.09.2026.

# 2. Что нельзя выдумывать (нет данных → плейсхолдер или вопрос)
- Параметры акции: % выгоды, срок, дедлайн, механика (только из ID_MECHANICS), кратность, порог чека, срок сгорания монет.
- Ассортимент: SKU, бренды, СТМ-линейки, цены, позиционирование — только из data/ассортимент.xlsx и подборок.
- Deeplink-ID приложения — только из data/deeplink.xlsx; иначе `dixyapp://app/catalog` или вопрос. В deeplink.xlsx дубли категорий не создавать. Строка «Кофе и чай» id=2305 нерабочая — замену из соседних строк не подбирать.
- Внешние факты (матчи, расписания, праздники) — только по верифицированному источнику с пометкой «проверить перед запуском».
- Проценты «Любимой категории» — только из data/Любимые категории <год> <месяц>.xlsx, колонка «Бонус %». Число ЛК: Друг 6, Лучший друг 8, докупка за монеты; в пуше на смешанную аудиторию — «минимум 5».
- Постоянные механики (любимый товар −20%, любимая категория, монеты) — только по data/evergreen_mechanics.md, читать при каждой вставке. Любимый товар ≠ любимая категория; любимую категорию в категорийные коммуникации не подмешивать.
- Скидки на сигареты и табак запрещены: ветки 610901, 610904, 610906 исключать из всех промо, подборок и моделей (зажигалки 610903 — не табак).
- Растворимый кофе не промотируется; герой кофейных серий — сладкое к кофе.
- Любимым товаром нельзя выбрать алкоголь (Елена 29.09.2026): в сериях пиво/вино -20% — на сыр или закуску к напитку, не «Выбери любимым товаром вино/пиво».

# 3. Папки, файлы, таблицы, серверы
- `data/` — только исходники Елены (ассортимент.xlsx, deeplink.xlsx, cvm_dictionaries.md, evergreen_mechanics.md, Любимые категории, расчёт КД, купоны на slip, I_PRODUCT_SCORE_NEW.xlsx). `output/` — всё, что генерируем (Excel, JSON, SQL, docx, скрипты сборки).
- Никаких .md-файлов с текстами/описаниями/отчётами — всё в чат. Исключение: справочники и SKILL.md по явной просьбе.
- Файл, который прислала/правила Елена, не редактировать: работать в копии `..._СУФФИКС.xlsx`, оригинал байт-в-байт (md5 до и после); на листы, о которых не просили, не лезть.
- Скрипты на прогон (`CVM_<нед>_26.sql`, `CVM_<месяц>_2026_I_PROMO.sql`, дельты) — одно рабочее имя, правки поверх, суффиксы `_1/_2` не плодить; историю держит git.
- Расчёт и отчёт — один файл (SQL: в конце SELECT-отчёт по форме I_CVM_EFFECT); побочные UPDATE-скрипты без просьбы не создавать.
- Подборки: каждая — отдельный файл И общий файл месяца `output/подборки_<месяц>_все.xlsx` (существующий читать и дополнять/пересобирать из исходников, не перезаписывать вслепую); без колонки «Цена».
- Google-таблица «CVM offline» (вкладки `CVM offline`, `PUSH`, `Параметры сегментов`) читается кодом через `sheets_client.py` (сервисный аккаунт в credentials/) — ссылку и скрины не просить. Запись — только после ОК; строки искать по НОМЕР и Номер msg, не по индексу (Елена правит лист параллельно); колонки с формулами (VLOOKUP, LEN, YEAR/MONTH/WEEKNUM) не перезаписывать — писать только целевые ячейки.
- Серверы: **kz** — код и агенты, без клиентских/финансовых данных ДИКСИ; **ru** — прод и все данные, доступен только через kz. Любой перенос файлов на сервер — сначала полный список, потом ОК, потом копирование (в data/ и output/ бывают персональные данные и пароли). Google API с kz недоступен — таблицы читать с Mac или с ru. Перед деплоем договариваться с соседними сессиями (кто деплоит, чей HEAD).
- Mac Елены не трогать: не открывать ссылки/браузер/программы, не поднимать туннели, не менять ~/.ssh и настройки. «Открой на kz» = на сервере.
- Ничего не размещать вовне (артефакты, хостинг, внешние сервисы) — только локально/localhost.
- Секреты (`credentials/`, `.env`) никуда не копировать и не печатать.

# 4. Словари и источники
- `SEGMENT` в I_CVM_CONTACT: 1 Новые, 2 Активные, 3 ВЦ (высокоценные / Активные LFL), 4 Случайные, 5 Отток, 6 Спящие. Типовые фильтры: Активные/Новые → (1,2,3); Отток+Спящие → (5,6); широкая → (1,2,3,5,6) без Случайных; частотные → (2,3) без Новых.
- `ID_SEGMENT` шапки I_PROMO (другой словарь!): 1 Новые, 2 Отток, 3 Спящие, 4 Активные, 6 Активные (дети), 9 Активные (животные), 10 Активные (алкоголь), 11 Активные (готовая еда), 12 Случайные, 28 ВСЕ оффлайн, 30 Активные (вино), 31 Активные (полуфабрикаты), 32 Активные (ПП). Полный список — data/cvm_dictionaries.md.
- `ID_MECHANICS`: 4 Активируемая скидка, 5 Купон, 7 Коммуникация, 8 Кэшбек X баллов, 16 Кэшбек активируемый, 17 Предначисление бонусов с активацией (в справочнике 01.06 нет — уточнено у заказчика). `ID_CHANNEL`: 1 PUSH, 4 SLIP.
- Миссии `I_MISSION` (при `MAIN is not null`) — названия дословно из data/cvm_dictionaries.md: «Правильное питание», «Готовая еда», «Дети», «Питомцы», «Пиво» + «Снеки», «Вино» + «Просекко (игристое)» (просекко в «Вино» не входит). Латинские WINE/PETS/CHILDREN устарели.
- Пороги жизненного цикла (от max(DATA) чеков): Активные — покупка в последние 6 недель; Новые — первая покупка в последние 6 недель; Отток — 6–15 недель; Спящие — больше 15 недель.
- `data/ассортимент.xlsx`: PRODUCT_NAME, ID_PRODUCT_EXTERNAL (SKU ID = без суффикса `_0`), ID_CATEGORY_5/4/3_ext, COUNT_SHOPS, COUNT_CHECK, AVG_PRICE — строки по городам, агрегировать по SKU. Цена категории = AVG_PRICE, взвешенная по COUNT_CHECK. Человеческие имена категорий cat5 — `data/I_PRODUCT_SCORE_NEW.xlsx`, колонка I_CATEGORY_5.
- «N видов X» считать как уникальные ID_PRODUCT_EXTERNAL внутри категорийных кодов с фильтром широкой представленности, не regex по названиям.
- В листе CVM offline колонка **«Категория»** хранит сами коды категорий (плоский список через перенос строки) — только для категорийных скидок/кешбэков; у коммуникаций и «все товары» кодов нет. «cat5» — внутренний термин, Елена так не говорит.
- Аудитории по размеру — лист «Параметры сегментов» (ВСЕГО / Есть PUSH и APP по сегментам и каналам offline/omni/e-commerce).

# 5. Терминология и написание (везде)
- «кешбэк» (не кэшбек/кэшбэк/кешбек); кешбэк не склонять: «Кешбэк 20% на X».
- Выгода символом: «-20%», не «минус 20%» и не «скидка 20%» в заголовках; слово «скидка» — только в условиях.
- Обращение на «ты»: «Купи», «Выбери», «Активируй»; никаких «Вы/Купите».
- Валюта лояльности — монеты, не баллы (кроме исторического названия «Баланс баллов»).
- «В ДИКСИ всегда приятные цены.» — единственная форма фразы о ценах, отдельным предложением; в монетных пушах — «Приходи в ДИКСИ — у нас ещё и цены приятные на все необходимые продукты, и ассортимент достойный.». Прямо «низкие цены» не писать.
- Механика любимого товара — дословно: «Выбери любимым товаром <продукты> и получай -20% при каждой покупке.»
- Слип-купоны в PUSH-сетку не входят; «Баланс баллов» — регулярный сервисный пуш, «Списание бонусов» — акционный под конкретное событие, не путать.

# 6. Люди и доступы
Контакты ДИКСИ и Manzana, параметры серверов и учёток — только в памяти проекта на Mac, в скиллы и на kz не переносить.

# 7. Чистка нейросетевого стиля (любой клиентский текст)
Перед выдачей вычистить:
- канцелярит: «осуществлять», «производить», «являться», «данный», «в рамках», «в целях», «приобрести», «реализовать»;
- оценочные пустышки: «уникальный», «инновационный», «оптимальный», «премиальный», «по-настоящему», «действительно», «огромный», «невероятный»;
- связки-пустышки: «стоит отметить», «важно понимать», «в современном мире», «в нашем магазине вы найдёте», «спешим сообщить», «приятно сообщить», «не упустите шанс»;
- штампы сетей: «свежесть каждый день», «лучшие цены в городе», «качество, которому доверяют», «всё для вашей семьи».

Замены: «осуществить покупку» → «купи»; «получить возможность» → «получить»; «в рамках акции» → «по акции»; «данный товар» → «этот товар»; «скидка составляет 20%» → «-20%»; «спешим сообщить» → удалить и начать с выгоды.

Правила: глагол вместо отглагольного существительного; конкретика (цифра, категория, дедлайн) вместо обобщения; короткая фраза вместо длинной; три прилагательных подряд — два убрать. Тест: прочитать вслух. Если текст подходит любой сети без правки — в нём нет конкретики; если не читается на одном дыхании — дробить.

# 8. Согласованность набора текстов (2+ текста одной акции или эпизода)
Пуш, купон, описание и баннер одной акции проверять вместе:
- категория и продукт названы **одинаково** во всех текстах (не «виноград» в пуше и «столовый виноград» в купоне);
- бренд и SKU пишутся одинаково;
- цифра выгоды звучит в сообщении один раз, в остальных текстах набора не повторяется без нужды;
- дедлайн в одном формате («до 06.09» везде, не «до воскресенья» в пуше и «до 6 сентября» в купоне);
- условия акции, сегмент и название механики совпадают между текстами;
- голос один: без перехода «бодрый пуш → канцелярит в купоне»;
- длины пропорциональны формату, знаки препинания единообразны.
