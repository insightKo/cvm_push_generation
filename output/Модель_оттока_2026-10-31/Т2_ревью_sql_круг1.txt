3. #kg: BSD = NULL создавал колонку int, UPDATE обрезал разброс группы до целого. Теперь CAST(NULL AS float).
4. Списки колонок групп категорий (@gcols/@gsel/@gnames/@galias и @g в CREATE TABLE): SELECT @v += ... ORDER BY порядок не гарантирует; при расхождении между списками колонки групп молча сдвинулись бы. Заменено STRING_AGG ... WITHIN GROUP (ORDER BY g) (порядок один во всех).
5. #ef2: коррелированные подзапросы по #ev (CCI без индекса, ≈ 2 млн строк #ef) заменены одним соединением; результат тот же (FAV_PROD_N без выбора = 0, FAV_CAT_N = NULL — как было).

8. Разовое расписание в прошлом не сработает никогда: если файл применён после 07.11.2026 15:00, старт через 5 минут.
9. ITEM_W.CHECKS: count(*) → count(DISTINCT ID_CHECK) (как в Н2а; при нескольких строках клиент × товар в чеке count(*) завышал чеки). Если в I_CLIENT_ITEM_DAY строка = чек × товар, результат тот же.
10. #vc (виртуальные карты): TRY_CAST к bigint и на стороне справочника (неявное преобразование нечислового номера роняло запрос).
11. transaction_date: CAST → TRY_CAST (порядок WHERE и CAST не гарантирован).
12. I_CVM_CHURN_FIRST в NOT EXISTS (режим inc): убран (nolock) на целевой таблице INSERT (ошибка 1065).
13. AGE tinyint: мусорные даты рождения (возраст > 255) → NULL вместо переполнения.
14. #days: окно −406 → −408 дней (в високосный год начало окна LFL «год назад от D − 41» уходит на день раньше; эталон CVM_CONTACT_UPDATE 393–417 даёт точно год назад).

Тот же результат без сортировки 100 млн: LAG один раз по #h (PARTITION BY ID_CONTACT ORDER BY WEEKNUMBER, ID_ORGANIZATION → PREVW), затем агрегирование:
   cnt = count(*) по (E, SL, клиент, орг.); s = sum(CASE WHEN PREVW >= SL+E-55 THEN WEEKNUMBER-PREVW END); n = count(CASE WHEN PREVW >= SL+E-55 THEN 1 END); AVG_DW = round(CASE WHEN cnt = 1 THEN 56 ELSE s/nullif(n,0) END, 0)
