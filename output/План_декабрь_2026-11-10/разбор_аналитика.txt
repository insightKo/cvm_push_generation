3. Отдельного декабрьского множителя данные не показывают: сдвиг ноября–декабря 2025 к тем же механикам в другие месяцы +0,5 ± 1,9 ₽ на клиента. В прогноз — 1,0.
4. При ежемесячном повторе эффект не падает: +0,06 ± 0,55 ₽ на каждый следующий повтор, 13 серий. Еженедельный повтор проверен один раз (ноябрь 2025, «Вернём 300 с 1000»): 1-я и 3-я волны около 0. Сложение акций у одного клиента по витринам не видно — нужен запрос (раздел 8).
5. Таргетинг повышает ₽ на клиента, но не общий объём. Пример: монеты в списках «Отток+Спящие» — 2,9 ₽ на клиента в среднем. Если взять Отток и вернувшихся (35 % списка), выходит 7,2 ₽, и это 86 % всего Доп ТО списка.
6. Потолок декабря по прогнозным коэффициентам: 74 млн (ДИ 23–126) за 4 волны «лучшая механика каждому сегменту каждую неделю». Со слипами и онлайном 88–97 млн. Совпадает с лучшими месяцами факта (дек-25 78,7, июн-26 81,3).

В фактах есть одна возможность, которая масштабируется до сотен миллионов: крупное начисление 200–400 монет. Это три A/B/C-теста по 10 тыс. клиентов (гипотеза, раздел 7).

1. МЕТОДИКА
==================================================================================================
Источник — dbo.I_CVM_EFFECT, строки CHANNEL_ID = 0 («Все каналы»): 397 акций со стартом с 03.10.2025 по 30.07.2026. Из оценки исключено 66 акций: «КГ несопоставима» = 1 — 10; нет КГ в оценке — 14; проверка «до старта» не проведена — 11; в оценке меньше половины ЦГ — 31 (онлайн-списки «Аффинитивные», где в оценке 0,2–45 % ЦГ). В расчёте 331 акция. Для разреза по сегменту давности прочитаны слои dbo.I_CVM_EFFECT_CG (только SELECT с nolock, скрипт прошёл ревью sql-senior): 157 305 строк периода «итого» с IN_TOTAL = 1, офлайн- и онлайн-база. Колонки X_FROM, X_TO и X_BAND в витрине пустые. Поэтому сумма «до» ячейки посчитана как TO_BEFORE_TG / CLIENTS_TG. Единица расчёта — «акция × сегмент». Для офлайн-акций сегмент — давность на старте по слоям: Новые, Активные (вместе с ВЦ и LFL), Отток (6–15 недель), Спящие (больше 15 недель). Доп ТО сегмента — сумма офлайн- и онлайн-слоёв этого сегмента. Списки 2026 года «Отток» на деле содержат Отток и Спящих вместе: на старте 26 % Оттока, 65 % Спящих и 9 % уже Активных (11 акций с монетами, слои I_CVM_EFFECT_CG). Доп ТО этих вернувшихся разложен поровну на клиента Оттока и Спящих. Случайные, аффинитивные и все онлайн-акции посчитаны по итогу акции. «₽ на клиента» = Σ Доп ТО итого / Σ клиентов ЦГ в оценке × доля клиентов в оценке («В оценке ЦГ» / «Клиентов ЦГ»): Новые 0,955, Активные 0,988, Отток 0,996, Спящие 0,901, Случайные 0,997. Получается рубль на клиента СПИСКА ЦГ, и прогноз = коэффициент × клиенты ЦГ в списке. Поэтому у 101075 здесь 51,8 ₽ вместо 54,5 ₽ в витрине: в витрине делят на клиентов в оценке. Ошибка акции — (ДИ до − ДИ от) / 3,92 из витрины, ошибка сегмента — √Σ ADD_TO_SE² слоёв. Скидка — «Скидка всего» / «Клиентов ЦГ». PL — по формуле витрины: (Доп ТО × 0,3 − скидка) / 1,15.

Поправка на «проклятие победителя» — эмпирический Байес в три уровня. Уровни: ячейка (сегмент × механика × длительность × выгода × порог) → семейство (сегмент × механика × длительность) → механика × длительность по всем сегментам. Разбросы на каждом уровне оценены из данных методом DerSimonian–Laird:
- τ между повторами одной акции считается по механике: монеты без порога 2,36 ₽; «Вернём N р. с X» 14,1 ₽ (его даёт волна 101075/101076); скидка на чек, целевые монеты и категорийный кешбэк — 0;
- между размерами выгоды внутри семейства — 0,35 ₽;
- между сегментами — 0,46 ₽ в среднем, у «Вернём N р.» 7,6 ₽;
- между механиками — 1,37 ₽ вокруг среднего канала 0,93 ₽.
Собственную оценку ячейки тянет к среднему уровня выше с весом B = τ² / (τ² + V), где V — ошибка выборки плюс τ² повторов, делённое на число акций. Механику с одной акцией тянет к среднему канала. Так одиночная сильная волна получает малый вес: 101162 (87,2 ₽) → 3,3 ₽, 101271 (15,5 ₽) → 1,3 ₽. Устойчивые семейства из 6 акций почти не двигаются: монеты 50 р. Активным 4,40 → 4,55 ₽. Метод симметричен: слабые ячейки поднимаются к среднему. Где поднятие больше 1 ₽, это написано в комментарии CSV, и ячейка помечена «осторожно». Годность для прогноза:
- «да» — прогнозная оценка > 0, нижняя граница ДИ > 0, не меньше 2 акций, не меньше 100 тыс. клиентов, нет КГ ниже плана, оценку не подняли больше чем на 1 ₽;
- «нет» — прогнозная или сырая оценка ≤ 0, а также тематические рассылки;
- «осторожно» — всё остальное.
Тематические рассылки исключены потому, что разброс между их повторами больше эффекта: разбор 101402 в октябре показал шум вокруг нуля, у 101317 сырая оценка 75,7 ₽ при ошибке ±77.

Запрос 1. КГ волны 2 «Вернём 300 с 1000»: почему у 101075 и 101076 КГ 2,7 % и 1,9 % вместо 10 %.
  SELECT o.ID_PROMO, o.CONTROL_GROUP, count(*) AS N, min(o.<дата загрузки строки>) AS D1, max(o.<дата загрузки строки>) AS D2
  FROM dbo.I_PROMO_OFFER o WITH (NOLOCK)

  GROUP BY o.ID_PROMO, o.CONTROL_GROUP;
  Колонку даты загрузки уточнить у sql-senior. Если КГ волны 2 дочищали после розыгрыша (например, исключали получивших прошлую волну), сравнение смещено, и 101075/101076 надо убрать из аналогов.
Запрос 2. Складываются ли эффекты у одного клиента. Для пар одновременно шедших акций с разными списками на одних клиентах — например, монеты Оттоку и кешбэк 50 % на категорию в одну неделю: 101266 и 101268/101270 (04–13.06), 101155 и 101153/101151 (02–12.01). ЦГ акции A делится на «есть в ЦГ B» и «нет в B», КГ A — так же. Доп ТО A считается отдельно в двух частях по методике процедуры (слои давности, выравнивание по «до»).
  Набросок первой части (без чеков):
  SELECT a.ID_PROMO, a.CONTROL_GROUP, CASE WHEN b.ID_CONTACT IS NULL THEN 0 ELSE 1 END AS IN_B, count(*) AS N
  FROM dbo.I_PROMO_OFFER a WITH (NOLOCK)
  LEFT JOIN dbo.I_PROMO_OFFER b WITH (NOLOCK) ON b.ID_CONTACT = a.ID_CONTACT AND b.ID_PROMO = @B AND b.CONTROL_GROUP = 0
  WHERE a.ID_PROMO = @A
  GROUP BY a.ID_PROMO, a.CONTROL_GROUP, CASE WHEN b.ID_CONTACT IS NULL THEN 0 ELSE 1 END;
  Если пересечение есть, вторая часть — Доп ТО по частям через процедуру эффекта с фильтром клиентов. Это решение по методике: сначала словами с Еленой.
Запрос 3. Кто 6 млн клиентов без пуша, по сегментам — чтобы применить коэффициенты слипов по сегменту.
  SELECT c.SEGMENT, count(*) AS N
  FROM dbo.I_CVM_CONTACT c WITH (NOLOCK)
  WHERE c.ID_ORGANIZATION = 1 AND c.HAS_PUSH = 0 AND NOT EXISTS (SELECT 1 FROM dbo.I_GLOBAL_CG g WITH (NOLOCK) WHERE g.ID_CONTACT = c.ID_CONTACT)
  GROUP BY c.SEGMENT;
  У регистраций с 18.09.2026 HAS_PUSH = 0 почти у всех (0,6 % вместо ~53 %), поэтому «без пуша» завышено. Признак уточнить у sql-senior.
