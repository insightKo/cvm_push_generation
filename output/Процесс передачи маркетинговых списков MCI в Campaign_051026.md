**Описание процесса: push со стороны MCI, передача батчами по API**

**Дата:** 05.10.2026

## 1. Назначение процесса

Ежедневная автоматическая передача готовых маркетинговых списков клиентов из MCI в Campaign. Инициатор передачи — MCI; Campaign принимает батчи по API и делает списки доступными в сегментаторе для коммуникаций и механик лояльности. Файлы, S3 и CSV в процессе не используются: все списки передаются батчами — JSON в теле запроса, идентификатор клиента — `contact_crmguid`.

## 2. Участники и зоны ответственности

| Участник | Ответственность |
|---|---|
| Джоб MCI (mci_model) | Сборка списков за 2 рабочих дня до старта акции; нарезка на батчи; передача в окно 06:00–10:00 (до 4 попыток); контроль отчётов; сверка и доотправка потерянных строк; журнал передач; алерты |
| API Campaign | Доступность приёмника в окне 06:00–10:00; валидация и сопоставление с базой; отчёт по каждому батчу в пределах SLA 30 минут; сверка по запросу; списки в сегментаторе к 11:00 |
| Команда CVM (MCI) | Реакция на алерты; ручная загрузка при исчерпании окна; сверка несопоставленных со своей базой |
| Команда Campaign | Разбор инцидентов SLA; разбор валидных несопоставленных контактов (качество базы) |

## 3. Расписание дня

| Время | Событие |
|---|---|
| Ночь | Ночной джоб MCI собирает списки клиентов (за 2 рабочих дня до старта акций) и режет их на батчи |
| 06:00 | Старт передачи: MCI отправляет батчи всех готовых списков в API Campaign |
| 06:00–10:00 | Окно передачи: при недоступности API или ошибке — повтор через 1 час, максимум 4 попытки (06:00 / 07:00 / 08:00 / 09:00) |
| +30 минут на батч | SLA Campaign: отчёт о загрузке по каждому принятому батчу |
| До 11:00 | Сверки и доотправки завершены; все списки со статусом `completed` доступны в сегментаторе |
| В течение дня | Пересборки и дельты списков копятся на стороне MCI и уходят следующим утром в то же окно |

## 4. Шаги процесса

| Шаг | Исполнитель | Действие | Результат |
|---|---|---|---|
| 1. Сборка | Джоб MCI | Ночной джоб собирает списки клиентов по правилам отбора (за 2 рабочих дня до старта акции) | Готовые списки `contact_crmguid` |
| 2. Нарезка | Джоб MCI | Каждый список режется на батчи фиксированного размера; небольшой список — один батч | Очередь батчей на передачу |
| 3. Передача | Джоб MCI | С 06:00 батчи уходят в `POST /lists/import`: первый батч списка — `replace`, следующие — `append` | `import_id` по каждому батчу |
| 4. Загрузка | Campaign | Валидация, сопоставление `contact_crmguid` с базой; отчёт в пределах 30 минут: передано / загружено / не сопоставлено (с перечнем) | Отчёт по каждому батчу |
| 5. Контроль | Джоб MCI | Проверка критерия завершения по каждому списку: передано = загружено + не сопоставлено | Статус `completed` или `incomplete` |
| 6. Сверка | Джоб MCI + Campaign | При `incomplete`: `GET /lists/{код списка}` — количество и состав; вычисление потерянных строк | Перечень потерянных строк |
| 7. Доотправка | Джоб MCI | Потерянные строки уходят батчем `append`; максимум 2 цикла «сверка → доотправка», далее алерт и ручной разбор | Список доведён до `completed` либо алерт |
| 8. Публикация | Campaign | Список со статусом `completed` доступен в сегментаторе (не позднее 11:00) | Список готов к использованию |
| 9. Журнал | Джоб MCI | Фиксация итогов дня: батчи, количества, статусы, время отчётов, просрочки SLA, перечни несопоставленных | Запись в журнале передач |

## 5. Статусы батча

| Статус | Значение | Действие MCI |
|---|---|---|
| `queued` / `processing` | Батч принят, обрабатывается (в пределах SLA 30 минут) | Ожидание отчёта; таймер SLA |
| `completed` | Каждая строка батча получила конечный статус: загружена или не сопоставлена | Зачесть батч; перечень несопоставленных — в журнал |
| `incomplete` | Есть строки без конечного статуса (потеряны при передаче) | Сверка состава → доотправка потерянных батчем `append` (максимум 2 цикла) |
| `failed` | Батч не обработан (ошибка на стороне Campaign) | Повтор в окне передачи; после окна — алерт |

## 6. Критерий завершения списка

Список считается загруженным, когда по всем его батчам выполняется равенство: **передано = загружено + не сопоставлено** — то есть каждая переданная строка получила конечный статус.

- **«Загружено»** — контакт сопоставлен с базой Campaign и включён в список.
- **«Не сопоставлено»** — контакта нет в базе Campaign. Это конечный статус, а не ошибка передачи: контакт фиксируется в перечне и **повторно не отправляется**. Бесконечная догрузка исключена по построению.
- Перечень несопоставленных MCI сверяет со своей базой: контакт удалён или ошибочен у нас — исключается из эталона списка; контакт валиден — передаётся Campaign на разбор качества базы (вне утреннего цикла).

## 7. Обработка отклонений

| Отклонение | Действие |
|---|---|
| API Campaign недоступен или вызов завершился ошибкой | Повтор через 1 час внутри окна 06:00–10:00, максимум 4 попытки |
| Окно передачи исчерпано (4 неудачные попытки) | Алерт команде CVM; ручная загрузка существующим механизмом; запас по срокам — списки готовятся за 2 рабочих дня до старта |
| Отчёт по батчу не пришёл за 30 минут | Инцидент на стороне Campaign: фиксация в журнале MCI, эскалация по договору |
| Статус `incomplete` (потерянные строки) | Сверка состава → доотправка только потерянных батчем `append`; максимум 2 цикла, далее алерт и ручной разбор |
| Контакт не сопоставлен | Повторно не отправляется; перечень — в журнал, сверка со своей базой, валидные — Campaign на разбор |
| Дневной цикл не завершён к 11:00 | Инцидент на стороне Campaign (если батчи переданы в срок); эскалация по договору |

## 8. Параметры регламента

| Параметр | Значение | Примечание |
|---|---|---|
| Окно передачи MCI | 06:00–10:00 | Старт 06:00 |
| Попытки передачи | 4, интервал 1 час | 06:00 / 07:00 / 08:00 / 09:00 |
| SLA отчёта Campaign | ≤ 30 минут на батч | Просрочка = инцидент Campaign |
| Завершение дневного цикла | Не позднее 11:00 | Включая сверки и доотправки |
| Размер батча | Например, до 50 тыс. контактов | Фиксируется в контракте |
| Циклы «сверка → доотправка» | Максимум 2 | Далее алерт и ручной разбор |
| Идентификатор клиента | `contact_crmguid` | Как в v1 |

*Все значения параметров — предлагаемые; финально фиксируются в регламенте и договоре с Campaign. Нарушение SLA — инцидент на стороне Campaign.*
